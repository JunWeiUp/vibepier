# Binary file transfers / 二进制文件传输

Uploaded images/attachments, conversation and project-image previews, workspace MP4s and APKs negotiate an independent file capability through the existing authenticated, encrypted session RPC. Production Android requires the binary file channel for these bodies, including when Bluetooth carries the control negotiation. An unavailable helper or IP route returns an explicit update/connection error. Legacy body-chunk fixtures remain only in the review APK; the production app does not fall back to them. A missing local helper does not advertise APK binary support; no plaintext control fallback is added.

## Routes and authorization / 路径与授权

`VibePierFileServer`, a signed child bundled beside the Mac app/CLI executable, listens on an ephemeral HTTPS port. It generates an in-memory P-256 TLS certificate; Android pins the exact SHA-256 received inside the encrypted offer. Only that connection uses the pin; global trust and hostname policies are unchanged. The Mac issues independent random 256-bit read/write capabilities for one device, operation, scope, immutable file and offset. Capabilities expire after ten minutes, reject replayed bodies, and are revoked on cancellation, trust changes or completion. The helper receives no pairing keys, provider credentials or desktop access; its private stdin pipe issues capabilities. It exits when the parent closes the pipe. Incoming sockets/handshakes, active files, buffers and file sizes are bounded.

The phone races body-free HEAD probes to authenticated LAN addresses, public IPv6 candidates and the configured HTTPS relay. It selects a reachable route before transmitting a body; a failed candidate does not serially delay the other routes. Public IPv6 must be reachable through both networks and the Mac firewall. IPv4 NAT traversal, STUN/ICE and automatic router port mapping are not implemented; a private or carrier-NAT address does not become public merely because the relay connection exists. There is no automatic second-route body replay after a partial/uncertain transfer. The relay accepts file registrations only with a fresh authenticated host proof using existing nonce/replay checks. Bodies stream through bounded `io.Pipe` buffers with backpressure, not relay storage. Independent one-use producer/consumer tokens prevent cross-file access; disconnect, completion, cancellation and expiry close pipes. Nginx file locations must disable request/response buffering. Existing WebSocket/control settings and room secrets are preserved. Public file requests honor the existing explicit `VIBEPIER_RELAY_PROXY` setting and environment proxy policy; authenticated LAN connections bypass HTTP proxies.

## Data and durability / 数据与落盘

Attachments, image previews, videos and APKs use raw binary bodies inside HTTPS, with no additional application-layer encryption. Thus the relay can read image, video and APK content; this reduced confidentiality was explicitly accepted by the user. Device/session authorization and expected hashes remain inside the original encrypted control channel. Mac attachment completion requires the receiving worker's final fsync, imports into the original device/session attachment record, and verifies the complete SHA-256/image format before success. Uploading never submits an AI message. Byte-send progress stays below 100% until completion is confirmed.

APK bytes use HTTPS transport protection without extra application-layer encryption. Consequently the relay can read APK content; it still cannot issue phone control actions or change the authenticated expected size/hash. Android downloads a continuous byte stream, writes/syncs in batches of up to 1 MiB, and resumes from the last durable file length. A new capability binds each requested offset. Full digest/package validation precedes the unchanged system install confirmation and signing checks. Download, verification and installation remain distinct.

上传图片、会话/项目图片、视频及 APK 都通过独立二进制通道传输，只保留 HTTPS，不做额外应用层加密。用户已明确接受这一隐私调整：公网服务器能读取图片、视频和 APK 内容。设备授权、作用域、随机短期凭据、摘要和安装签名检查保留。手机并行探测局域网直连、公网 IPv6 直连和中继，在发送正文前选定可达通道；公网 IPv6 仍需两端网络及防火墙允许。目前不支持 IPv4 NAT 自动打洞或自动端口映射，不能把私网地址当成公网可达，部分传输失败不自动重放正文。APK 按最多 1 MiB 批量落盘，以实际同步长度续传；收到文件不等于安装成功，系统确认仍需用户操作。

## Build and validation / 构建与验证

Mac packaging builds the helper from `services/relay/cmd/vibepier-file-server` with Go and signs it before the containing bundle. CLI archives include the sibling helper. Build/package commands never run it or install keys/settings. `services/relay/nginx-vibepier-relay.conf` includes the additional file location.

Go tests cover exact body sizes, truncation/extra bytes, capability replay, cancellation/device isolation, APK offset binding and real HTTPS cloud producer/consumer cleanup. Opt-in `VIBEPIER_BINARY_HELPER_TEST_EXECUTABLE=<helper>` Swift tests use synthetic authorization/private directories to exercise TLS upload and attachment manifest completion. Emulator `binary-files` uses synthetic data and a separately launched test helper; no providers or APK installers run. Synthetic loopback/emulator speeds must not be described as real-device Wi-Fi throughput.

构建包含 Go 文件助手，按与应用一致的发布方式签名，不修改系统证书或全局 TLS 设置。测试区分单元测试、模拟器网络测速和真机验收；模拟数据不发送给 AI，也不触发系统安装。

## Media snapshots and preview / 媒体快照与预览

Providers first validate the selected phone/session and opaque image ID or workspace MP4 path. JPEGs (480 px thumbnail, up to 2048 px large preview) and immutable full MP4 snapshots are exported into private temporary files with SHA-256. The file helper issues the `media` capability; the control reply contains only size/type/hash/route metadata, never JPEG or MP4 Base64. A video uses one offer and one continuous download, rather than one RPC per 128 KiB. Android verifies the complete size/hash before display/playback and keeps capabilities out of media URLs. Images decode off the UI thread with bounded concurrency and 16 MiB bitmap caching. Active download progress extends the 30-second idle deadline, with a two-minute total image deadline, so a progressing download is not discarded merely for exceeding the initial request timer. Cancellation and timeouts end the pending UI, disconnect sockets and cancel known capabilities; helper expiry bounds snapshots left by lost/cancelled responses. File access allowlists and device authorization remain intact.

Mac 先校验手机、会话、图片 ID 或项目内 MP4 路径，再生成权限0700/0600的临时快照及完整SHA-256。回复只包含元数据和短期凭据，视频不再按128KiB逐轮RPC下载。图片缩略480px、大图最高2048px；Android先验证完整大小及摘要再显示/播放，图片解码不占主线程，并发有界、缓存16MiB。取消和超时结束界面等待并断开连接；已知凭据取消，遗漏回包的快照由助手到期清理。不扩大会话文件范围或手机授权。

Images open in a full-screen viewer, initially fitting the whole image while retaining compact close/retry controls and system insets. Pinch to zoom, drag a magnified image to inspect details, and double-tap to zoom in or return to the fitted view. Zoom and panning stay within bounded image limits; opening another preview resets its view. The thumbnail remains visible while the large image loads, and loading failure retains the retry and close actions. Zoom uses the existing decoded image and does not request a higher-resolution export.

图片尽量全屏打开，默认显示完整图片，保留系统安全边距及简洁的关闭/重试入口；双指缩放、放大后拖动可查看局部，双击可放大或还原。缩放和拖动范围有边界，每次打开预览重置视图。大图加载期间保留缩略图，失败时仍可重试或关闭。缩放使用现有解码图片，不会另行请求更高分辨率快照。
